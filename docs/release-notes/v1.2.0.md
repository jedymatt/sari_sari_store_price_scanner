# v1.2.0+7 — Mga Utang

**Version:** `1.2.0+7` (previous release on Play: `1.1.0+5`)
**Date:** 2026-08-25

> `1.2.0+6` was built but never accepted by the Play Console — it was signed with the
> debug key, because `android/app/build.gradle.kts` had never been wired to
> `android/key.properties`. That is fixed in #23, and the build number moves to `+7`.
> Users are still on `1.1.0`, so this release is their first sight of Mga Utang.

### ceb

The Play Console has no `ceb` (Cebuano) listing language, so Cebuano release notes cannot
be published to the store. The single Cebuano line folded into the en-US block above is
the workaround — Play allows any text in the en-US field, and the 500-character limit
leaves room for it.

This is a **store listing** limitation only. The app itself still ships full Cebuano via
`lib/l10n/app_ceb.arb`, and the in-app language picker is unaffected. Devices set to
Cebuano will see the English store listing but a Cebuano app.

## What shipped

- **Mga Utang** - per-customer credit ledger. Customers (name, optional phone), debt
  (utang) and payment (bayad) entries with notes and dates, running balance per
  customer, total outstanding across all customers, and customer search. (#15, #17)
- **Trash** - customers are soft-deleted instead of removed. Restore them, or let them
  auto-purge 30 days after being trashed.
- Cebuano translations for every new string.
- Android toolchain upgrade and AGP built-in Kotlin. (#19, #21)
- App settings moved to an `InheritedWidget` instead of `findAncestorStateOfType`. (#19)
- **Release signing wired to the upload key.** `flutter build appbundle --release` used to
  produce a debug-signed bundle, which is why `+6` was rejected. Gradle now reads
  `android/key.properties`. (#23)

## Before uploading

- Run `flutter test` and `flutter analyze`, and make sure both are clean.
- Build the bundle: `flutter build appbundle --release`.
- Check the Play Console: version code must be higher than anything already uploaded.
  `1.1.0+5` is live, so `+7` clears it. (`+4` and `+5` shipped without git tags — the
  tags stop at `v1.1.0+3`, so git is not a reliable record of what Play has.)
- Confirm the bundle is signed with the upload key, not the debug key:

  ```bash
  KT="/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool"
  "$KT" -printcert -jarfile build/app/outputs/bundle/release/app-release.aab | grep SHA256
  ```

  Expect `21:5E:62:E9:CD:09:26:8B:A6:9D:6D:0B:C7:C7:23:FD:2B:24:EF:BC:F6:B0:98:C4:6A:33:03:BE:5A:9C:74:E4`,
  which should match **App integrity → App signing → Upload key certificate** in the
  Play Console.
